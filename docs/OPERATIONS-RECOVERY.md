# النسخ والاستعادة وتسوية البيانات التاريخية

تصدير لوحة الإدارة يضم جداول مختارة لأغراض العمل. للاحتفاظ بنسخة قابلة للاستعادة استخدم أرشيف PostgreSQL، مع نسخة منفصلة من الأصول المخزنة خارج القاعدة. يغطي الأرشيف المخطط وبيانات قاعدة واحدة. إعدادات المزود والأدوار المشتركة وأسرار التشغيل تحتاج نسختها التشغيلية الخاصة.

## النسخ

1. جهّز أدوات PostgreSQL `pg_dump` و`pg_restore` و`psql` بإصدار متوافق مع الخادم، ومجلد نسخ خاص خارج المستودع بأذونات مناسبة وقرص مشفّر.
2. حمّل `DARK_CRM_BACKUP_URL` في بيئة الطرفية من مدير الأسرار. استخدم اتصال PostgreSQL مباشرًا دون وسيط pooling. الأكثر أمانًا إعداد `sslmode=verify-full` وشهادات الثقة المناسبة لعميل PostgreSQL. الأداة لا تقرأ ملفات `.env` تلقائيًا.
3. نفّذ `npm run db:backup -- <new-bundle-folder>`. تختار الأداة مجلدًا جديدًا، وتكتب أرشيفًا وملف SHA-256 بعد نجاح إنشاء الأرشيف. المجلد الذي يفتقد ملف `manifest.json` غير مكتمل.
4. نفّذ `npm run db:backup:verify -- <bundle-folder>` قبل النقل وبعده. يختبر الأمر البصمة وقائمة الأرشيف. احتفظ بالنسخة في مخزن خاص يفرض التشفير وأذونات وصول وسجل مراجعة، مع سياسة احتفاظ متفق عليها.
5. صدّر أصول ImageKit إلى مخزن خاص بإمكانية استعادة المسارات الأصلية، بما فيها صور العقارات ووثائقها الخاصة. سجّل مع الأرشيف توقيت نسخة الأصول، مسارها في المخزن، وبصمتها وسجل مفاتيحها. صلاحية الوصول إلى ملفات الإنتاج خلال تمرين الاستعادة ليست مطلوبة. استخدم حساب أصول اختبار معزول عند تجربة الملفات الخاصة.

الأرشيف يشمل بيانات حساسة وتجزئات كلمات المرور. احتفظ ببيانات دخول PostgreSQL ومفاتيح ImageKit وJWT ومزودي التكامل في مدير الأسرار. لا تلحقها بالأرشيف أو بسجل تمرين الاستعادة. يدعم مسار النسخ رابطًا مع `sslmode` فقط؛ أزل خيارات Prisma أو Neon الخاصة بالعميل مثل `schema` و`pgbouncer` من رابط هذه الأداة.

## تمرين الاستعادة

1. أنشئ محليًا قاعدة فارغة ومعزولة باسم مثل `dark_crm_restore_rehearsal`. استخدم خادم PostgreSQL محليًا فعليًا وبيئة منفصلة عن الخدمات الحية. لا تمرر اتصال إنتاج عبر نفق محلي.
2. اضبط `DARK_CRM_RESTORE_URL` لهذه القاعدة داخل الطرفية. نفّذ `npm run db:restore:local -- <bundle-folder> dark_crm_restore_rehearsal`. تتحقق الأداة من الاسم والوجهة والبصمة وفراغ القاعدة، وتنفذ الاستعادة في معاملة واحدة.
3. وجّه نسخة التطبيق التجريبية للقاعدة المستعادة مع مفاتيح تشغيل تجريبية. أبق التكاملات والإشعارات الحية غير مفعلة. جرّب قراءة البيانات والعلاقات ودورة البيع وعينة من الأصول باستعمال مخزن الأصول المعزول.
4. قارن أعداد السجلات والمجاميع المالية وحالة الهجرات مع المصدر المتفق عليه، وسجّل نتيجة التمرين وزمنه. راجع مؤشرات `scripts/review-historical-data.sql`. حافظ على أذونات النسخ أثناء التمرين وبعده.

## القيم المالية والعلاقات التاريخية

- بعد الهجرتين `20261127_review_integrity` و`20261128_decimal_sync` على النسخة المعزولة، شغّل `psql -X -v ON_ERROR_STOP=1 -f scripts/review-historical-data.sql` مع اتصال النسخة المعزولة. الاستعلام يأخذ المجاميع وأعداد القيم المفقودة والمتعارضة وخارج النطاق، وأعداد الاشتراكات اليتيمة. ينبغي تفسير الفروق القديمة قبل اعتماد النتائج.
- تستكمل هجرة Decimal القيم الناقصة القابلة للتمثيل وتزامن الأعمدة القديمة عند الكتابة. الأعمدة الحالية والبيانات التاريخية تبقى لحين اكتمال المقارنة. إذا لم تكن هجرة Foundation مطبقة، راجع حدود القيم على النسخة المعزولة قبلها، لأن ملفها الأصلي يجري تعبئة أولية للأعمدة.
- تبقى العمولات اليدوية أو غير المؤكدة دون صفقة. جهّز ملفًا خاصًا باسم `reviewed-commissions.csv` بالأعمدة `commission_id,deal_id` بعد مراجعة مستندات العملية. راجع عدد الروابط وجرّب `scripts/link-reviewed-commissions.sql` على النسخة المعزولة. يرفض حالة التعارض بالكامل ويحافظ على قيم العمولات الأصلية.
- عندما تصل أعداد المخالفات إلى صفر بعد مراجعتها، تحقّق على نسخة معزولة من `VALIDATE CONSTRAINT` لقيود `PushSubscription_userId_fkey` و`PropertyOwnership_percentage_range` و`PropertyOwnership_effective_dates`. لا نحذف صفًا قديمًا تلقائيًا ولا نفترض أن مجموع الملكية التاريخي صحيح.

مراجع الأدوات: [pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html) و[pg_restore](https://www.postgresql.org/docs/current/app-pgrestore.html).
