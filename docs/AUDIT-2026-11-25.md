## خطة تنفيذ مقترحة

1. **تحديد النسخة المرجعية والتجهيز:** مقارنة التغييرات العشرة واعتماد SHA مستهدف، وتجهيز قاعدة اختبار مستقلة ونسخة بيانات منزوعة الحساسية. القبول: تحديد الفرع والـ SHA، إثبات استقلال قاعدة الاختبار، ونجاح البناء المعزول. لا دمج أو نشر أثناء المراجعة.
2. **الأمان والصلاحيات:** مراجعة معالجة JWT في النسخة المستهدفة، ملكية push، حدود الطلبات ومصفوفة الأدوار. القبول: اختبارات API حقيقية تثبت فشل المصادقة عند غياب السر ومنع الوصول المتقاطع والتلاعب والطلبات المتزامنة.
3. **سلامة البيانات والنسخ:** جرد الهجرات الفعلية قراءةً فقط، تصميم علاقات المال والملكية وخطة تراجع ونسخ شاملة. القبول: تطبيق وترحيل واستعادة على قاعدة معزولة مع فحص أعداد العلاقات والمجاميع، دون أي تعديل للإنتاج.
4. **الصحة الوظيفية:** إصلاح إجماليات المحاسبة والتكرار وتغييرات الحالات وتحديد وظيفة التكاملات. القبول: حالات مكررة ومتزامنة وأكثر من 100 حركة واختبار كل حالة نجاح وفشل عبر API والواجهة.
5. **الأداء والواجهات:** pagination للكتالوج ولوحات العملاء والعقارات، ثم تقليل استعلامات المزامنة. القبول: نتائج كاملة عبر الصفحات وقياسات زمن وحجم واستعلامات على بيانات اختبار بحجم متفق عليه.
6. **إكمال التغطية:** حصر كل صفحة ومسار API ووظيفة وربطها بالمواصفات واختبارات الصلاحيات والواجهات، ثم حساب نسبة كل وحدة بمعيار محدد ومعلن. القبول: مصفوفة تغطية كاملة ونتائج قابلة لإعادة الإنتاج؛ لا تعتمد أية نسبة قبل ذلك.
